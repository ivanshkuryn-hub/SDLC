# 0002 — Использование файлового хранилища (CSV/TXT) вместо СУБД

## Статус
Принято (Accepted)

## Контекст и постановка задачи
Системе необходимо хранить базу продуктов, настройки пользователя и записи дневника питания. В проекте зафиксировано ограничение: приложение автономно и запускается как один исполняемый `.jar` файл.

## Драйверы решения
- Простота развертывания (не нужно устанавливать сервер БД).
- Автономность (база продуктов поставляется вместе с приложением).
- Легкость резервного копирования (пользователь может просто скопировать папку с данными).

## Рассмотренные варианты
1. **Файловое хранилище (CSV для продуктов, TXT/Properties для логов и настроек)** — встроено в JDK, не требует зависимостей.
2. **SQLite (через JDBC)** — реляционная БД в одном файле, требует подключения драйвера и написания SQL-запросов.
3. **PostgreSQL/MySQL** — требуют установки сервера.

## Итог решения
Выбран вариант 1 (Файловое хранилище). Для учебного проекта и базы в ~30 продуктов полноценная СУБД избыточна и усложняет сборку.

## Последствия
**Хорошо:** Ноль зависимостей для хранения данных, прозрачный формат (можно открыть в блокноте).
**Плохо:** Нет транзакций и SQL-запросов. При росте базы до тысяч записей поиск по CSV будет медленным (потребуется миграция на SQLite).
