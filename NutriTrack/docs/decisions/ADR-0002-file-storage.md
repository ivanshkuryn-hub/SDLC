# ADR-0002 — Использование файлового хранилища CSV/TXT вместо СУБД

## Статус
Принято (Accepted)

## Дата
18.11.2026

## Контекст и постановка задачи
NutriTrack — локальное однопользовательское веб-приложение. Система хранит локальную базу продуктов, настройки пользователя, записи дневника питания и сведения об объёме выпитой воды.

Приложение должно запускаться на компьютере пользователя и работать без интернета. Установка отдельного сервера базы данных не входит в область первой версии.

## Драйверы решения
- Автономная работа без внешних сервисов.
- Простота сборки и запуска.
- Отсутствие необходимости устанавливать и администрировать СУБД.
- Возможность резервного копирования каталога данных.
- Простота проверки данных в учебном проекте.

## Рассмотренные варианты
- **CSV/TXT/Properties** — локальные файлы базы продуктов, дневников и настроек.
- **SQLite** — встроенная реляционная база в одном файле, требующая JDBC-драйвера.
- **PostgreSQL/MySQL** — серверные СУБД, требующие установки и настройки.

## Принятое решение
Выбрано файловое хранение. Используются:
- `products.csv` — локальная база продуктов;
- `settings.properties` — настройки приложения;
- `meals/YYYY-MM-DD.csv` — CSV-дневник питания за дату с полями времени, продукта, веса порции и рассчитанных значений КБЖУ;
- `water/YYYY-MM-DD.csv` — CSV-учёт воды за дату с полями времени и объёма в миллилитрах;
- `weight.csv` — история измерений массы тела с датой и значением веса.

Каталог пользовательских данных отделяется от ресурсов и файлов сборки. Питательные значения продуктов в `products.csv` задаются на 100 г.

## Последствия
**Положительные:**
- Не требуется отдельная СУБД.
- Данные легко копировать для резервного сохранения.
- Форматы доступны для просмотра текстовыми средствами.
- Решение соответствует масштабу первой версии.

**Ограничения:**
- Файловое хранилище не предоставляет полноценные транзакции и SQL.
- Необходимо самостоятельно обеспечивать корректность формата и согласованность записей.
- При одновременной записи требуется защита от конфликтов доступа.
- При существенном росте данных поиск по файлам может стать менее эффективным.

## Связь с требованиями
- `REQ-SEC-001` — локальное хранение пользовательских данных.
- `REQ-REL-001` — сохранность данных.
- `SYS-FUNC-006` — поиск продуктов в локальной базе;
- `SYS-FUNC-012` / `REQ-FUNC-016` — сохранение измерений массы тела;
- `SYS-INF-001` — конфигурация и сборка приложения.
