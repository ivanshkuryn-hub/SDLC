# Описание дизайна программного обеспечения (SDD) — NutriTrack

**Версия:** 1.0  
**Статус:** Черновик  
**Дата:** 13.11.2026

## 1. Введение
Данный документ описывает архитектуру и дизайн десктопного приложения NutriTrack. В документе представлены ключевые архитектурные представления (viewpoints), объясняющие, как система будет построена для удовлетворения требований, описанных в SRS и системных требованиях.

## 2. Обзор дизайна и точки зрения
Выбрана **слоистая (Layered) архитектура**, разделяющая графический интерфейс (UI), бизнес-логику и работу с файлами. Это обеспечивает слабую связанность компонентов и упрощает тестирование.

Для описания архитектуры выбраны следующие представления (Viewpoints):
- **Context (Контекст):** Взаимодействие системы с внешним миром.
- **Composition (Композиция):** Разбиение системы на крупные модули.
- **Logical (Логическое):** Внутренняя структура пакетов и классов.
- **Information (Информационное):** Модели данных и файлы хранения.

## 3. Проектные представления (Design Views)

### 3.1 Контекстное представление (Context View)
Приложение NutriTrack является автономным (Standalone).
- **Пользователь** взаимодействует с системой через графический интерфейс (Swing).
- **Файловая система** используется для чтения базы продуктов (`products.csv`) и сохранения дневника питания (`meals.txt`).
- **Внешние сервисы** отсутствуют (нет сетевых запросов, согласно ADR-0002).

### 3.2 Композиционное представление (Composition View)
Система разделена на три основных компонента:
1. **Presentation Layer (UI):** Окна и панели Swing (Главное окно, Дневник, Сканер, Графики).
2. **Domain Layer (Бизнес-логика):** Сервисы для расчёта КБЖУ, управления целями и логикой сканирования.
3. **Data Access Layer (Работа с данными):** Репозитории для чтения/записи CSV и текстовых файлов.

### 3.3 Логическое представление (Logical View)
Пакеты Java (внутри `src/main/java/by/bsuir/nutritrack/`):
- `ui`: Классы `MainFrame`, `FoodDiaryPanel`, `ScannerPanel`, `WaterPanel`.
- `service`: Классы `NutritionService`, `BarcodeService` (обертка над ZXing), `ChartService` (обертка над JFreeChart).
- `repository`: Классы `ProductRepository`, `DiaryRepository`, `SettingsRepository`.
- `model`: Сущности `Product`, `MealEntry`, `WaterEntry`.

### 3.4 Информационное представление (Information View)
В качестве хранилища используются текстовые файлы (согласно ADR-0002).
**Сущность Product (в `products.csv`):**
`barcode;name;kcal;protein;fat;carbs`
**Сущность MealEntry (в `meals_YYYY-MM-DD.txt`):**
`date;barcode;weight_g`

### 3.5 Представление развертывания (Deployment View)
Приложение поставляется в виде одного исполняемого файла `nutritrack.jar`. Для запуска требуется JVM (Java 17). Приложение работает в оконном режиме ОС Windows или Linux.

## 4. Архитектурные решения (Decisions)
В процессе проектирования были приняты следующие ключевые решения (подробнее в ADR):
- **ADR-0001:** Использование ZXing для распознавания.
- **ADR-0002:** Файловое хранилище (CSV/TXT) вместо СУБД.
- **ADR-0003:** Использование Java Swing для UI.
- **ADR-0004:** Напоминания через SystemTray.
