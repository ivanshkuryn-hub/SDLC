# Спецификации вариантов использования NutriTrack

## Общие сведения

Основной актёр системы — Пользователь (ACT-01).

Каждый вариант использования описывает отдельную
пользовательскую задачу и последовательность
взаимодействия с приложением.

---

## UC-01. Просмотреть главную страницу

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю просматривать
сводную информацию о питании, потреблении воды
и динамике массы тела за текущий день.

**Предусловия:**

- Локальное приложение NutriTrack запущено.
- Пользователь может открыть веб-интерфейс
  по адресу `http://localhost:8080`.

**Основной поток событий:**

1. Пользователь открывает веб-интерфейс приложения.
2. Система отображает главную страницу.
3. Система получает данные дневника питания
   за текущую дату.
4. Система отображает суммарное количество
   потреблённых калорий, белков, жиров и углеводов.
5. Система отображает дневную цель по калориям
   и прогресс её достижения.
6. Система отображает прогресс потребления воды
   относительно дневной цели.
7. Система отображает графики калорий и воды
   за последние семь дней.
8. Система отображает график изменения массы тела.
9. Пользователь просматривает полученную информацию.

**Альтернативные потоки:**

Отдельные альтернативные сценарии просмотра
главной страницы в исходной документации не определены.

**Постусловия:**

Главная страница отображена. Пользователь получил
сводную информацию о своих показателях и может
перейти к другим функциям приложения.

**Связанные требования:**
REQ-FUNC-003, REQ-FUNC-006, REQ-FUNC-010,
REQ-FUNC-014, REQ-FUNC-016.

## UC-02. Просмотреть графики прогресса

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю анализировать
изменения потребления калорий, воды и массы тела
с помощью графиков приложения.

Графики размещаются на главной странице
и не требуют перехода на отдельный экран.

**Предусловия:**

- Приложение запущено.
- Главная страница доступна пользователю.

**Основной поток событий:**

1. Пользователь открывает главную страницу.
2. Система получает дневные итоги потребления
   калорий и воды за последние семь дней.
3. Система получает сохранённые измерения массы тела.
4. Система формирует графики калорий и воды.
5. Система формирует график изменения массы тела.
6. Система отображает графики на главной странице.
7. Пользователь анализирует динамику показателей.

**Альтернативные потоки:**

Отдельные альтернативные сценарии просмотра
графиков в исходной документации не определены.

**Постусловия:**

Графики прогресса отображены пользователю.

**Связанные требования:**
REQ-FUNC-010, REQ-FUNC-016.

## UC-03. Просмотреть дневник питания

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю просматривать
список съеденных продуктов за выбранную дату,
а также суммарные значения калорий и БЖУ.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть экран дневника питания.

**Основной поток событий:**

1. Пользователь открывает экран дневника питания.
2. Система устанавливает текущую дату по умолчанию.
3. Пользователь при необходимости выбирает другую дату.
4. Система получает записи питания за выбранную дату.
5. Система отображает список продуктов, массу порций
   и рассчитанные значения КБЖУ.
6. Система отображает суммарные значения калорий
   и БЖУ за выбранную дату.
7. Пользователь просматривает дневник питания.

**Альтернативные потоки:**

В исходной документации отдельные альтернативные
сценарии просмотра дневника не определены.

**Постусловия:**

Дневник питания за выбранную дату отображён.
Записи пользователя не изменены.

**Связанные требования:**
REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003.

## UC-04. Добавить продукт вручную

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю самостоятельно
добавить съеденный продукт в дневник питания,
указав его название, фактический вес порции
и пищевую ценность на 100 г.

Система автоматически рассчитывает значения
калорий, белков, жиров и углеводов
для указанной порции.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть экран дневника питания.

**Основной поток событий:**

1. Пользователь открывает экран дневника питания.
2. Система устанавливает текущую дату по умолчанию.
3. Пользователь при необходимости выбирает другую дату.
4. Пользователь вводит название продукта.
5. Пользователь указывает фактический вес порции.
6. Пользователь вводит калорийность и содержание
   белков, жиров и углеводов на 100 г продукта.
7. Пользователь подтверждает сохранение записи.
8. Система проверяет корректность введённых значений.
9. Система рассчитывает КБЖУ для указанной порции.
10. Система сохраняет запись в дневнике питания
    за выбранную дату.
11. Система отображает обновлённый дневник
    и суммарные значения за день.

**Альтернативные потоки:**

А1. Введены некорректные значения.

Система сообщает об ошибке проверки данных
и предлагает исправить введённые значения.

А2. Возникла ошибка сохранения.

Система сообщает об ошибке операции.
Приложение продолжает работу.

**Постусловия:**

После успешного выполнения прецедента
запись сохранена в дневнике питания
за выбранную дату. Дневные итоги обновлены.

**Связанные требования:**
REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003.

## UC-05. Добавить продукт по штрих-коду

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю найти продукт
в локальной базе по фотографии штрих-кода
и добавить его в дневник питания.

Для распознавания используется библиотека ZXing.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть экран сканера.
- Локальная база продуктов доступна.

**Основной поток событий:**

1. Пользователь открывает экран сканера.
2. Система отображает элемент загрузки изображения.
3. Пользователь выбирает фотографию штрих-кода
   в формате JPEG или PNG.
4. Пользователь отправляет изображение на обработку.
5. Система проверяет наличие файла и его формат.
6. Система передаёт изображение компоненту ZXing.
7. ZXing распознаёт штрих-код и возвращает
   его строковое значение.
8. Система отображает результат распознавания.
9. Система выполняет поиск штрих-кода
   в локальном файле products.csv.
10. Система отображает карточку найденного продукта
    с пищевой ценностью на 100 г.
11. Пользователь указывает фактический вес порции.
12. Система рассчитывает КБЖУ для указанной порции.
13. Система отображает рассчитанные значения.
14. Пользователь подтверждает добавление продукта.
15. Система сохраняет запись в дневнике питания
    за текущую дату.
16. Система обновляет информацию о дневнике питания.

**Альтернативные потоки:**

А1. Штрих-код не распознан.

Система сообщает, что не удалось распознать
штрих-код на загруженном изображении.

А2. Продукт отсутствует в локальной базе.

Система сообщает, что продукт не найден,
и предлагает выполнить ручной ввод.

А3. Загружен файл неподдерживаемого формата
или возникла ошибка обработки изображения.

Система отображает сообщение об ошибке
и предлагает повторить загрузку.

А4. Возникла ошибка сохранения записи.

Система отображает сообщение об ошибке.
Приложение продолжает работу.

**Постусловия:**

После успешного выполнения прецедента
продукт добавлен в дневник питания
за текущую дату.

При выполнении альтернативного сценария
пользователь получает соответствующее сообщение
или возможность ручного ввода.

**Связанные требования:**
REQ-FUNC-007, REQ-FUNC-008, REQ-FUNC-009.

## UC-06. Удалить запись питания

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю удалить
выбранную запись о съеденном продукте
из дневника питания.

После удаления система обновляет суммарные
значения калорий и БЖУ за выбранную дату.

**Предусловия:**

- Приложение запущено.
- Пользователь открыл дневник питания.
- В дневнике имеется запись, доступная для удаления.

**Основной поток событий:**

1. Пользователь открывает дневник питания.
2. Система отображает записи за выбранную дату.
3. Пользователь выбирает запись продукта.
4. Пользователь выполняет действие удаления записи.
5. Система удаляет выбранную запись.
6. Система пересчитывает суммарные значения
   калорий, белков, жиров и углеводов.
7. Система отображает обновлённый дневник питания.

**Альтернативные потоки:**

А1. При ошибке удаления или записи изменений
система отображает понятное сообщение.
Приложение продолжает работу.

**Постусловия:**

Выбранная запись удалена из дневника питания.
Суммарные значения за выбранную дату обновлены.

**Связанные документы:**
SRS, раздел 3.1.1 «Пользовательские интерфейсы»;
SDD, раздел 2.3 «Композиционное представление»;
SDD, раздел 2.5.2 «Дневник питания».

## UC-07. Экспортировать дневник в PDF

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю сформировать
PDF-отчёт с данными дневника питания
за выбранную дату и сохранить его на локальный компьютер.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть дневник питания.
- Дневник питания доступен для выбранной даты.

**Основной поток событий:**

1. Пользователь открывает дневник питания.
2. Система отображает записи за выбранную дату.
3. Пользователь выбирает дату, за которую необходимо
   сформировать отчёт.
4. Пользователь запускает экспорт дневника в PDF.
5. Система получает записи питания за выбранную дату.
6. Система формирует PDF-документ.
7. Система включает в отчёт список продуктов,
   вес порций, рассчитанные значения калорий и БЖУ,
   а также дневные итоги.
8. Система передаёт сформированный файл браузеру.
9. Пользователь сохраняет PDF-файл на локальный компьютер.

**Альтернативные потоки:**

В исходной документации отдельные альтернативные
сценарии экспорта PDF не определены.

**Постусловия:**

PDF-отчёт сформирован и передан пользователю
для сохранения на локальный компьютер.
Данные дневника питания не изменены.

**Связанные требования:**
REQ-FUNC-015.

## UC-08. Добавить воду

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю учитывать
выпитую воду с помощью быстрого добавления
или ручного ввода объёма.

Система сохраняет записи и обновляет дневной
объём потреблённой воды.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть экран учёта воды.

**Основной поток событий:**

1. Пользователь открывает экран учёта воды.
2. Система отображает дневной объём выпитой воды,
   быстрые кнопки добавления и поле ручного ввода.
3. Пользователь нажимает кнопку быстрого добавления
   250 мл или 500 мл.
4. Система увеличивает дневной объём
   на соответствующее значение.
5. Система сохраняет запись учёта воды
   за текущую дату.
6. Система обновляет отображаемый дневной объём
   и прогресс относительно дневной цели.

**Альтернативные потоки:**

А1. Ручное добавление воды.

Пользователь вводит произвольный объём воды
в соответствующее поле и подтверждает операцию.

Система проверяет введённое значение,
добавляет объём к дневному итогу,
сохраняет запись и обновляет прогресс.

А2. Введено некорректное значение.

Система отображает сообщение об ошибке
и предлагает исправить введённые данные.

**Постусловия:**

Запись об объёме выпитой воды сохранена.
Дневной объём и прогресс потребления воды обновлены.

**Связанные требования:**
REQ-FUNC-004, REQ-FUNC-005, REQ-FUNC-006.

## UC-12. Переключить тему

**Актёр:** Пользователь (ACT-01).

**Описание:**

Прецедент позволяет пользователю переключать
цветовую тему интерфейса NutriTrack
между светлым и тёмным оформлением.

Выбранная тема применяется ко всем основным
экранам приложения и сохраняется между запусками.

**Предусловия:**

- Приложение запущено.
- Пользователь может открыть веб-интерфейс.

**Основной поток событий:**

1. Пользователь открывает веб-интерфейс приложения.
2. Система отображает текущую цветовую тему.
3. Пользователь нажимает переключатель темы.
4. Система изменяет цветовую тему интерфейса.
5. Система применяет выбранное оформление
   ко всем четырём основным экранам.
6. Система сохраняет выбранную тему
   в settings.properties.
7. Пользователь продолжает работу
   с обновлённым оформлением приложения.

**Альтернативные потоки:**

Отдельные альтернативные сценарии переключения
цветовой темы в исходной документации не определены.

**Постусловия:**

Выбранная цветовая тема применена
ко всем основным экранам приложения.
Настройка сохранена для последующих запусков.

**Связанные требования:**
REQ-FUNC-013.
