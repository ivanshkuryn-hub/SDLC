## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}

Настоящий документ фиксирует требования к локальному веб-приложению NutriTrack, предназначенному для ведения дневника питания и учёта потребления воды. В документе определены задачи продукта, его функциональные возможности, ограничения и качественные характеристики. Спецификация предназначена для заказчика, менеджера проекта, разработчиков и специалистов по тестированию и служит основой для разработки системных требований и проектной документации.

### 1.2 Область применения продукта {#12-product-scope}

NutriTrack — это локальное веб-приложение для персональных компьютеров, предназначенное для ежедневного учёта потребляемых калорий и выпитой воды. Дополнительно приложение отображает содержание белков, жиров и углеводов (БЖУ) в продуктах и суммарные значения БЖУ за день без установки отдельных целевых значений. Приложение запускается на компьютере пользователя, а взаимодействие с ним осуществляется через веб-браузер по локальному адресу.

Продукт позволяет добавлять продукты в дневник вручную или с помощью загрузки фотографии штрих-кода, отслеживать прогресс по калориям и воде с помощью графиков, настраивать дневные цели по калориям и воде и получать напоминания о необходимости пить воду во время работы с приложением.

В первую версию продукта входят:

- Ведение дневника питания с подсчётом калорий и отображением БЖУ.
- Учёт водного баланса (быстрые кнопки и ручной ввод).
- Распознавание продуктов по штрих-коду с загруженного изображения.
- Визуализация прогресса (графики за неделю).
- Напоминания о необходимости пить воду во время работы с приложением.
- Настройка дневных целей по калориям и объёму воды.
- Переключение между светлой и тёмной темами интерфейса.

В первую версию продукта не входят: синхронизация с облачными сервисами, интеграция с фитнес-браслетами (Apple Health, Google Fit), социальные функции и функции медицинской диагностики.

## 2. Обзор продукта {#2-product-overview}

### 2.1 Перспектива продукта {#21-product-perspective}

NutriTrack представляет собой самостоятельное локальное веб-приложение, предназначенное для автоматизации учёта питания и потребления воды. Без такой системы пользователю приходится вести записи в бумажных блокнотах или отдельных таблицах, что усложняет подсчёт калорий и анализ динамики потребления воды. Приложение объединяет основные операции учёта в одной системе.

Взаимодействие с пользователем осуществляется через веб-браузер. Серверная часть реализуется на Java 17 с использованием Spring Boot и Spring MVC. Для формирования HTML-страниц применяется Thymeleaf. Контроллеры, бизнес-логика и средства работы с локальными файлами входят в состав одного приложения.

Приложение запускается локально на компьютере пользователя и доступно по адресу `http://localhost:8080`. В первой версии не предусматривается размещение приложения на внешнем сервере или организация удалённого доступа.

База продуктов и пользовательские данные хранятся в локальных файлах на компьютере пользователя.

### 2.2 Функции продукта {#22-product-functions}

Приложение NutriTrack предоставляет следующие основные функциональные возможности:

- **Учет питания.** Ведение дневника съеденных продуктов с автоматическим подсчетом калорий и отображением белков, жиров и углеводов (БЖУ). Суммарные значения БЖУ за день доступны пользователю как дополнительная информация.
- **Учет воды.** Фиксация выпитой жидкости за день с помощью быстрых кнопок (+250 мл, +500 мл) или ручного ввода.
- **Сканирование штрих-кодов.** Загрузка фотографии штрих-кода продукта для автоматического распознавания и добавления его в дневник.
- **Целеполагание.** Настройка дневной цели по калориям на главном экране и дневной цели по воде на экране «Учёт воды». Значения сохраняются между запусками. Отдельные целевые значения для белков, жиров и углеводов не устанавливаются.
- **Визуализация.** Построение графиков прогресса за неделю по потреблённым калориям и выпитой воде относительно соответствующих дневных целей.
- **Напоминания.** Отображение уведомлений непосредственно в веб-интерфейсе о необходимости сделать перерыв и попить воды.
- **Тёмная тема.** Возможность переключения цветовой схемы веб-интерфейса между светлой и тёмной.

### 2.3 Ограничения продукта {#23-product-constraints}

При разработке первой версии NutriTrack необходимо учитывать следующие ограничения:

- Продукт реализуется в виде локального веб-приложения, доступного через браузер.
- Технологический стек: Java 17, Spring Boot и Spring MVC для серверной обработки запросов; Thymeleaf для формирования веб-интерфейса; HTML, CSS и Bootstrap для оформления страниц. Ресурсы веб-интерфейса должны храниться локально и не загружаться из внешних источников.
- Архитектура приложения строится на основе MVC.
- Автономность: приложение должно работать без подключения к интернету. Данные хранятся локально в файлах CSV/TXT.
- Для работы приложения необходимо наличие Java 17 и современного веб-браузера на компьютере пользователя.
- Доступ к приложению осуществляется через локальный адрес `http://localhost:8080`.
- Распознавание штрих-кодов осуществляется путём анализа загруженного пользователем фотоизображения (JPEG/PNG), без сканирования веб-камерой в реальном времени.
- Планируемый срок реализации проекта составляет 6 недель.
- Бюджет проекта ограничен, предпочтение отдаётся экономичным решениям и бесплатным библиотекам.

### 2.4 Характеристики пользователей {#24-user-characteristics}

В системе предусматриваются две основные категории пользователей.

| Категория пользователя | Основные характеристики | Предоставляемые возможности |
|---|---|---|
| Пользователь, следящий за весом (любитель) | Человек, желающий снизить или поддерживать вес. Обладает базовыми навыками работы с персональным компьютером. | Ввод данных о питании и воде, просмотр графиков, настройка дневных целей по калориям и воде |
| Спортсмен и фитнес-энтузиаст | Пользователь, которому важен контроль калорий, дополнительная информация о БЖУ и потребление воды. | Все возможности любителя, а также просмотр статистики и настройка дневных целей по калориям и воде |

Пользовательский интерфейс должен быть понятен пользователям с различным уровнем компьютерной подготовки. Для всех категорий необходимо обеспечить простой процесс добавления продуктов и воды.

### 2.5 Допущения и зависимости {#25-assumptions-and-dependencies}

- Допущения: пользователь имеет персональный компьютер с установленной Java 17 и современным веб-браузером. Пользователь знаком с основами работы с веб-интерфейсами. Наличие подключения к интернету не требуется.
- Зависимости: для реализации веб-приложения используется Spring Boot и Spring MVC, для формирования HTML-страниц — Thymeleaf, для распознавания штрих-кодов — библиотека ZXing, для построения графиков — JFreeChart. Для хранения данных используется локальная файловая система с применением форматов CSV/TXT.

## 3. Требования {#3-requirements}

### 3.1 Внешние интерфейсы {#31-external-interfaces}

#### 3.1.1 Пользовательские интерфейсы {#311-user-interfaces}

Система должна предоставлять веб-интерфейс, доступный через современный веб-браузер по локальному адресу `http://localhost:8080`. Интерфейс формируется с использованием Thymeleaf, HTML, CSS и Bootstrap.

Предусматриваются четыре основных экрана веб-интерфейса:

| Экран | Назначение |
|---|---|
| Главная | Отображение суммарных значений потреблённых калорий и БЖУ за текущий день, прогресса по калориям и воде, графиков за последние 7 дней и элемента настройки дневной цели по калориям. На экране размещается переключатель цветовой темы. |
| Дневник питания | Просмотр списка съеденных продуктов, добавление и удаление записей, отображение калорийности и содержания БЖУ. |
| Сканер | Загрузка изображения штрих-кода, отображение результата распознавания и найденной карточки продукта. |
| Учёт воды | Быстрое и ручное добавление выпитой воды, отображение прогресса относительно дневной цели, настройка дневной цели по воде и интервала напоминаний. |

Функции просмотра прогресса и настройки не выделяются в отдельные страницы: графики и настройка дневной цели по калориям размещаются на главном экране, а настройка дневной цели по воде и интервала напоминаний — на экране «Учёт воды». Переключатель цветовой темы доступен в общей части интерфейса. Переход между четырьмя основными экранами осуществляется с помощью элементов навигации веб-интерфейса. Ввод данных выполняется через формы и соответствующие элементы управления браузерной страницы. Для загрузки фотографии штрих-кода используется стандартный элемент выбора файла браузера.

Интерфейс должен быть интуитивно понятным и не требовать от пользователя специальных знаний.

#### 3.1.2 Аппаратные интерфейсы {#312-hardware-interfaces}

Специальные аппаратные интерфейсы не предусмотрены. Для работы с системой пользователю необходим персональный компьютер (или ноутбук) с операционной системой Windows 10+ или Linux, а также стандартные устройства ввода (клавиатура, мышь).

Для взаимодействия с веб-приложением используется установленный на компьютере веб-браузер. Загрузка фотографии штрих-кода осуществляется с локального устройства хранения данных через стандартный элемент выбора файла браузера. Использование веб-камеры и других специализированных устройств не требуется.

#### 3.1.3 Программные интерфейсы {#313-software-interfaces}

В первой версии NutriTrack предусматривается взаимодействие со следующими программными средствами и компонентами:

- **Операционная система.** Обеспечивает работу Java-виртуальной машины (JVM), локального сервера приложения и файловой системы.
- **Spring Boot.** Используется для запуска локального веб-сервера и управления компонентами приложения.
- **Spring MVC.** Обеспечивает обработку HTTP-запросов, поступающих от веб-браузера, и передачу данных между контроллерами и представлениями.
- **Thymeleaf.** Используется для формирования HTML-страниц на стороне сервера.
- **Веб-браузер.** Обеспечивает отображение пользовательского интерфейса и взаимодействие с приложением по адресу `http://localhost:8080`.
- **Библиотека ZXing.** Используется для декодирования загруженных изображений штрих-кодов.
- **Библиотека JFreeChart.** Используется серверной частью для построения графиков прогресса. Сформированные графики сохраняются или подготавливаются в формате PNG и передаются браузеру как изображения через локальные HTTP-маршруты приложения.
- **Файловая система.** Используется для хранения базы продуктов (`products.csv`), настроек пользователя и записей дневника питания и воды.

Браузер обменивается данными с серверной частью посредством HTTP-запросов внутри локального компьютера. Пользовательские данные не передаются на внешние серверы или в облачные сервисы.

### 3.2 Функциональные требования {#32-functional}

#### 3.2.1 Учёт питания

**REQ-FUNC-001 — Добавление продукта вручную**

- **Statement:** Система должна позволять пользователю добавлять продукт в дневник питания вручную, указывая название, фактический вес съеденного продукта, а также калорийность и содержание белков, жиров и углеводов в расчёте на 100 г продукта.
- **Rationale:** Обеспечение базовой возможности учёта питания.
- **Acceptance Criteria:** Пользователь может ввести данные в форму и сохранить запись. Запись отображается в списке за текущий день.
- **Verification Method:** Test.

**REQ-FUNC-002 — Автоматический подсчёт КБЖУ**

- **Statement:** Система должна автоматически пересчитывать калории и БЖУ в зависимости от указанного веса продукта.
- **Rationale:** Снижение вероятности ошибок при ручном подсчёте.
- **Acceptance Criteria:** При изменении фактического веса продукта система пересчитывает калорийность и количество белков, жиров и углеводов по формуле: значение на 100 г × фактический вес в граммах / 100. Полученные значения отображаются в интерфейсе. При ручном добавлении продукта пользователь вводит исходные значения калорийности и БЖУ на 100 г.
- **Verification Method:** Test.

**REQ-FUNC-003 — Просмотр суммарных значений за день**

- **Statement:** Система должна отображать суммарное количество потреблённых калорий и БЖУ за текущий день.
- **Rationale:** Предоставление пользователю сводной информации.
- **Acceptance Criteria:** На главном экране отображаются суммарные значения калорий и БЖУ за текущий день в текстовом или графическом виде. Для калорий может отображаться прогресс относительно установленной дневной цели; отдельные целевые значения для БЖУ не предусматриваются.
- **Verification Method:** Test.

#### 3.2.2 Учёт воды

**REQ-FUNC-004 — Быстрое добавление воды**

- **Statement:** Система должна предоставлять кнопки для быстрого добавления объёма воды (+250 мл, +500 мл).
- **Rationale:** Упрощение и ускорение процесса логирования.
- **Acceptance Criteria:** При нажатии на кнопку счётчик выпитой воды увеличивается на соответствующее значение.
- **Verification Method:** Test.

**REQ-FUNC-005 — Ручной ввод объёма воды**

- **Statement:** Система должна позволять пользователю вводить произвольный объём выпитой воды.
- **Rationale:** Возможность учитывать объём воды, не соответствующий значениям быстрых кнопок.
- **Acceptance Criteria:** Пользователь может ввести числовое значение объёма воды, после чего оно прибавляется к общему значению за текущий день.
- **Verification Method:** Test.

**REQ-FUNC-006 — Отображение прогресса по воде**

- **Statement:** Система должна отображать прогресс потребления воды относительно установленной дневной цели. Значение прогресса должно рассчитываться на основании выпитого объёма и целевого значения.
- **Rationale:** Визуальная мотивация пользователя.
- **Acceptance Criteria:** Шкала заполняется пропорционально выпитому объёму.
- **Verification Method:** Test.

#### 3.2.3 Сканирование штрих-кодов

**REQ-FUNC-007 — Загрузка фото штрих-кода**

- **Statement:** Система должна предоставлять возможность выбора и загрузки файла изображения (JPEG/PNG) с фотографией штрих-кода через веб-интерфейс.
- **Rationale:** Использование фото вместо ручного ввода.
- **Acceptance Criteria:** Пользователь может выбрать изображение с локального устройства с помощью стандартного элемента выбора файла браузера и отправить его на обработку.
- **Verification Method:** Test.

**REQ-FUNC-008 — Распознавание штрих-кода**

- **Statement:** Система должна декодировать загруженное изображение и извлекать строку штрих-кода.
- **Rationale:** Автоматизация ввода данных о продукте.
- **Acceptance Criteria:** Если на изображении есть чёткий штрих-код, система выводит его в виде строки.
- **Verification Method:** Test, Demonstration.

**REQ-FUNC-009 — Поиск продукта в локальной базе**

- **Statement:** Система должна искать распознанный штрих-код в локальном файле `products.csv`.
- **Rationale:** Получение КБЖУ для автоматического заполнения.
- **Acceptance Criteria:** Если продукт найден в локальной базе, отображается его карточка с названием и калорийностью, а также содержанием БЖУ на 100 г. После указания фактического веса съеденного продукта система рассчитывает значения для указанной порции. Если продукт не найден — выводится сообщение, после которого пользователь может внести данные о продукте вручную.
- **Verification Method:** Test.

#### 3.2.4 Визуализация прогресса

**REQ-FUNC-010 — Построение графика за неделю**

- **Statement:** Система должна строить график потребления калорий и воды за последние 7 дней.
- **Rationale:** Наглядное отображение динамики.
- **Implementation Constraint:** Графики формируются на сервере с помощью JFreeChart в формате PNG и передаются браузеру как изображения через локальные HTTP-маршруты приложения.
- **Acceptance Criteria:** На главном экране отображается линейный или столбчатый график с данными о потреблённых калориях и выпитой воде за последние 7 дней.
- **Verification Method:** Demonstration.

#### 3.2.5 Напоминания

**REQ-FUNC-011 — Настройка интервала напоминаний**

- **Statement:** Система должна позволять пользователю задавать интервал (в минутах) для напоминаний о воде.
- **Rationale:** Адаптация под привычки пользователя.
- **Acceptance Criteria:** Пользователь может установить интервал на экране «Учёт воды».
- **Verification Method:** Test.

**REQ-FUNC-012 — Отображение уведомления в веб-интерфейсе**

- **Statement:** Система должна периодически отображать на открытой странице веб-приложения уведомление о необходимости выпить воду с учётом интервала, заданного пользователем.
- **Rationale:** Привлечение внимания пользователя без использования системных уведомлений операционной системы.
- **Acceptance Criteria:** По истечении заданного интервала на открытой странице приложения должно появляться уведомление о необходимости выпить воду.
- **Verification Method:** Demonstration.

#### 3.2.6 Настройка внешнего вида

**REQ-FUNC-013 — Переключение тёмной темы**

- **Statement:** Система должна предоставлять пользователю возможность переключать цветовую тему веб-интерфейса между светлой и тёмной.
- **Rationale:** Повышение удобства использования приложения при различных условиях освещения и с учётом предпочтений пользователя.
- **Acceptance Criteria:** Пользователь может переключить светлую или тёмную тему с помощью элемента управления в общей части веб-интерфейса. После выбора оформление всех экранов приложения изменяется в соответствии с выбранной темой, а настройка сохраняется между запусками приложения.
- **Verification Method:** Test.

**REQ-FUNC-014 — Настройка дневных целей**

- **Statement:** Система должна позволять пользователю устанавливать и изменять дневную цель по калориям и дневную цель по объёму воды. Значения целей должны сохраняться в настройках приложения и использоваться при отображении прогресса.
- **Rationale:** Персонализация контроля потребления калорий и воды.
- **Acceptance Criteria:** Пользователь может задать и изменить дневную цель по калориям на главном экране, а дневную цель по воде — на экране «Учёт воды». После сохранения новые значения применяются для расчёта соответствующего прогресса и сохраняются между запусками приложения. Отдельные дневные цели для белков, жиров и углеводов не устанавливаются.
- **Verification Method:** Test.

### 3.3 Качество обслуживания {#33-quality-of-service}

#### 3.3.1 Производительность {#331-performance}

- **REQ-PERF-001 — Время запуска приложения:** Запуск локального сервера приложения и обеспечение доступности главной страницы должны занимать не более 3 секунд.
- **REQ-PERF-002 — Время распознавания:** Обработка загруженного изображения и распознавание штрих-кода должны занимать не более 2 секунд.

#### 3.3.2 Безопасность {#332-security}

- **REQ-SEC-001 — Локальность данных:** Все пользовательские данные должны храниться только на локальном диске компьютера пользователя. Обмен данными между браузером и серверной частью приложения осуществляется по локальному адресу `localhost`. Передача пользовательских данных за пределы компьютера не допускается.
- **REQ-SEC-002 — Валидация ввода:** Система должна проверять корректность вводимых числовых значений (например, вес не может быть отрицательным).

#### 3.3.3 Надёжность {#333-reliability}

- **REQ-REL-001 — Сохранность данных:** Данные не должны теряться при аварийном завершении работы (запись в файл должна происходить атомарно или с резервным копированием).
- **REQ-REL-002 — Обработка ошибок:** При некорректном изображении штрих-кода система должна выводить понятное сообщение, а не завершаться с ошибкой.

#### 3.3.4 Доступность {#334-availability}

- **REQ-AVAIL-001 — Доступность интерфейса:** Веб-интерфейс приложения должен оставаться доступным для взаимодействия во время выполнения операций обработки данных, включая распознавание загруженных изображений штрих-кодов.

#### 3.3.5 Наблюдаемость {#335-observability}

- **REQ-OBS-001 — Логирование ошибок:** Критические ошибки, включая проблемы чтения и записи файлов, должны фиксироваться в журнале приложения для последующего анализа.

### 3.4 Соответствие стандартам {#34-compliance}

- **REQ-COMP-001 — Лицензионная чистота:** Используемые библиотеки (ZXing, JFreeChart) должны иметь свободные лицензии (Apache 2.0, LGPL), допускающие коммерческое использование.

### 3.5 Проектирование и реализация {#35-design-and-implementation}

#### 3.5.1 Установка {#351-installation}

- **REQ-INST-001 — Простая установка:** Приложение должно распространяться в виде исполняемого файла `.jar`. Для запуска требуется установленная Java 17. После запуска приложения локальный веб-сервер должен стать доступен, а пользователь должен иметь возможность открыть NutriTrack в браузере по адресу `http://localhost:8080`.

#### 3.5.2 Сборка и поставка {#352-build-and-delivery}

- **REQ-BUILD-001 — Сборка через Maven:** Проект должен собираться с помощью Maven. Должен быть создан исполняемый JAR-файл.

#### 3.5.3 Распределение {#353-distribution}

Распределённое развертывание не предусматривается. NutriTrack является локальным однопользовательским приложением: серверная часть и веб-браузер работают на одном компьютере. Удалённое размещение и взаимодействие нескольких компьютеров не входят в область первой версии.

#### 3.5.4 Сопровождаемость {#354-maintainability}

- **REQ-MAINT-001 — Модульность:** Код должен быть разделён на логические слои: контроллеры обработки веб-запросов, бизнес-логику, представления веб-интерфейса и компоненты работы с локальными файлами. При реализации должны соблюдаться принципы объектно-ориентированного программирования.

#### 3.5.5 Повторное использование {#355-reusability}

- **REQ-REUSE-001 — Использование библиотек:** Для сканирования и графиков используются проверенные сторонние библиотеки, что снижает объём собственного кода.

#### 3.5.6 Переносимость {#356-portability}

- **REQ-PORT-001 — Кроссплатформенность:** Приложение должно работать в Windows 10+ и Linux (например, Ubuntu 20.04+).

#### 3.5.7 Стоимость {#357-cost}

Бюджет проекта ограничен. Используются только бесплатные инструменты и библиотеки.

#### 3.5.8 Сроки {#358-deadline}

Проект должен быть завершён в течение 6 недель с момента начала разработки.

#### 3.5.9 Доказательство концепции {#359-proof-of-concept}

- **REQ-POC-001 — Прототип сканера:** На ранних этапах необходимо создать прототип, подтверждающий возможность распознавания штрих-кода с фото с помощью ZXing.

#### 3.5.10 Управление изменениями {#3510-change-management}

- **REQ-CM-001 — Контроль версий:** Изменения в коде и документации должны фиксироваться в Git.

### 3.6 ИИ/МО {#36-aiml}

В первой версии NutriTrack не используются модели машинного обучения и технологии искусственного интеллекта. Распознавание штрих-кодов выполняется с помощью библиотеки ZXing и не относится к применению ИИ/МО.

## 5. Приложения {#5-appendixes}

### Приложение А. Словарь данных

Питательные значения калорийности, белков, жиров и углеводов в локальной базе продуктов `products.csv` задаются в расчёте на 100 г продукта. Пользователь указывает фактический вес съеденной порции, после чего система пересчитывает значения пропорционально этому весу.

| Файл | Формат | Описание |
|---|---|---|
| `products.csv` | CSV (barcode, name, kcal, protein, fat, carbs; питательные значения указаны на 100 г) | Локальная база продуктов; калорийность и БЖУ в каждой записи задаются на 100 г продукта |
| `settings.properties` | Ключ=Значение | Дневная цель по калориям, дневная цель по воде, интервал напоминаний и выбранная цветовая тема |
| `meals/YYYY-MM-DD.csv` | CSV | Дневник питания за день; каждая строка содержит время записи, идентификатор/штрих-код продукта, название, вес порции и рассчитанные значения калорий и БЖУ для этой порции |
| `water/YYYY-MM-DD.csv` | CSV | Учёт воды за день; каждая строка содержит время записи и добавленный объём в миллилитрах |
