# Дополнительные спецификации NutriTrack

## 1. Границы системы

NutriTrack рассматривается как локальное веб-приложение,
работающее на компьютере пользователя.

Взаимодействие с системой осуществляется через веб-браузер
по адресу `http://localhost:8080`.

Основным внешним действующим лицом является Пользователь.
Он взаимодействует с приложением через пользовательский
интерфейс и выполняет операции учёта питания, воды и массы тела.

В SRS выделены две категории пользователей:
пользователь, следящий за весом, и спортсмен или
фитнес-энтузиаст. Поскольку их действия в приложении
совпадают, в UML-модели они представлены общей ролью
«Пользователь».

## 2. Правила функционирования системы

### 2.1. Дневник питания

- Пользователь может выбрать дату дневника. При первом
  открытии используется текущая дата.
- При ручном добавлении пользователь указывает название
  продукта, массу порции и калорийность, белки, жиры
  и углеводы на 100 г.
- Значения КБЖУ для порции рассчитываются по формуле:
  значение на 100 г × масса порции / 100.
- Дневные итоги рассчитываются суммированием записей
  за выбранную дату.
- Отдельные дневные цели по белкам, жирам и углеводам
  не устанавливаются.
- При удалении записи дневные итоги пересчитываются.

### 2.2. Распознавание штрих-кодов

- Пользователь загружает изображение формата JPEG или PNG.
- Распознавание выполняется локально с использованием
  библиотеки ZXing.
- Полученный штрих-код используется для поиска продукта
  в файле `products.csv`.
- При обнаружении продукта система отображает его
  пищевую ценность на 100 г.
- Пользователь указывает массу порции и подтверждает
  добавление продукта в дневник.
- Запись, добавленная через сценарий штрих-кода,
  сохраняется за текущую дату.
- Если продукт не найден, система предлагает
  воспользоваться ручным вводом.
- Сканирование камерой в реальном времени не
  предусматривается.

### 2.3. Учёт воды и дневные цели

- Быстрое добавление воды выполняется кнопками
  250 мл и 500 мл.
- При ручном вводе пользователь указывает произвольный
  положительный объём воды.
- Дневной объём определяется суммой всех записей
  за соответствующую дату.
- Прогресс рассчитывается относительно установленной
  дневной цели по воде.
- Пользователь может изменять дневные цели по калориям
  и воде.
- Значения целей сохраняются в `settings.properties`.

### 2.4. Внешний вид приложения

- Пользователь может переключать светлую и тёмную темы.
- Выбранная тема применяется ко всем четырём основным
  экранам приложения.
- Настройка темы сохраняется между запусками.

### 2.5. Графики и масса тела

- На главной странице отображаются графики потребления
  калорий и воды за последние семь дней.
- Пользователь может добавлять измерения массы тела
  с указанием даты.
- График веса строится на основании сохранённых измерений
  в хронологическом порядке.
- Графики формируются с использованием JFreeChart
  в формате PNG и передаются браузеру через локальные
  HTTP-маршруты.

### 2.6. Экспорт PDF

- Пользователь выбирает дату дневника и запускает экспорт.
- PDF-отчёт содержит список продуктов, массу порций,
  рассчитанные значения калорий и БЖУ, а также дневные итоги.
- Сформированный файл передаётся браузеру для сохранения
  на локальный компьютер.

## 3. Правила хранения данных

| Данные | Место хранения | Назначение |
|---|---|---|
| База продуктов | products.csv | Поиск продуктов |
| Настройки и тема | settings.properties | Сохранение целей и темы |
| Записи питания | meals/YYYY-MM-DD.csv | Хранение дневника питания |
| Записи воды | water/YYYY-MM-DD.csv | Хранение потребления воды |
| Измерения веса | weight.csv | Хранение истории массы тела |

Все пользовательские данные хранятся локально.
Для хранения используются файлы CSV и Properties.
Система не использует внешнюю СУБД.

## 4. Нефункциональные ограничения

- Приложение должно работать без обязательного
  подключения к интернету.
- Доступ к приложению осуществляется по адресу
  `http://localhost:8080`.
- Для запуска требуется Java 17 и современный веб-браузер.
- Время запуска приложения и открытия главной страницы
  не должно превышать 3 секунд.
- Обработка изображения штрих-кода должна занимать
  не более 2 секунд в условиях целевой конфигурации.
- Распознавание изображения не должно блокировать
  обработку других HTTP-запросов.
- Некорректный ввод и ошибки файловых операций должны
  обрабатываться без аварийного завершения приложения.

## 5. Исключения из первой версии

В текущую модель не включаются:

- Напоминания о необходимости выпить воду.
- Облачная синхронизация пользовательских данных.
- Интеграция с Google Fit и Apple Health.
- Сканирование штрих-кодов камерой в реальном времени.
- Системные уведомления операционной системы.
- Отдельные дневные цели и графики по белкам, жирам
  и углеводам.
